# MaxPatrol VM: устранение уязвимостей (расширение Chrome)

Слой мобилизации устранения поверх MaxPatrol VM 28.0. Встраивается в интерфейс продукта: в левом меню появляется пункт «Устранение», который открывает рабочую область справа от меню. Обоснование и план: `../RESEARCH_расширение_для_процесса_VM.md`.

## Установка

1. `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное расширение» → папка `vm_remediation/`.
2. Нажмите иконку расширения на панели браузера: сервер (например `maxpvm.company.ru`), порт (пусто = как у страницы) и персональный токен из PT MC → Токены доступа. «Сохранить».
3. Откройте или обновите вкладку MaxPatrol VM. В левом меню после «Активы» появится пункт «Устранение».
4. Кнопка «Проверить» в окне расширения запрашивает версию продукта напрямую с сервера по токену; если из окна расширения сервер недоступен (самоподписанный сертификат принят только во вкладке), проверка идет через открытую вкладку сервера. После обновления расширения вкладку сервера нужно перезагрузить: окно предложит кнопку.
5. Несохраненный ввод в окне расширения не теряется при его закрытии (Chrome закрывает окно при переходе в другое окно): черновик восстанавливается при следующем открытии.

## Что внутри

- **Обзор.** Показатели процесса: открытые, просрочки по срокам (приказ ФСТЭК 117: критические 1 день, высокие 7), возраст, трендовые с EPSS/KEV, покрытие активов, топ узлов. Отчет для руководства в HTML, выгрузка JSON. Опционально срез 30 дней назад через `timepoint` (минуты).
- **Очередь устранения.** Открытые уязвимости, сгруппированные по ПО и версии (или пакетам Unix): одно обновление закрывает всю группу. Сортировка по устраняемому риску. Детали группы: CVE с внешними сигналами, узлы, CSV, массовая смена статуса в MaxPatrol (В работе, Исправляется до даты, Исключить с причиной, Вернуть в Новая).
- **CVE-контекст.** CVE с открытой страницы MaxPatrol или из текста: EPSS (FIRST), CISA KEV, NVD (CVSS 4.0, SSVC), БДУ ФСТЭК из офлайн-импорта, PoC на GitHub. Вердикт P0-P3 и срок устранения.
- **Настройки.** Источники и ключи, нормы сроков, импорт выгрузки БДУ (XML `<vul>` или CSV/TXT).

## Сценарии из Tenable, Qualys и Rapid7 (версия 0.3)

По исследованию интерфейсов лидеров рынка добавлены вкладки:
- **Риск активов**: балл 0-1000 по открытым уязвимостям узла с весом значимости актива и разложением по драйверам (трендовые, critical, важные, эксплойт, high, прочие). Аналог Asset Exposure Score (Tenable) и TruRisk (Qualys). Фильтр по значимости, CSV.
- **Исключения**: реестр исключенных уязвимостей по причинам (с комментарием и без), «сомнительные» исключения (трендовые, с эксплойтом, CVSS 9+) с кнопкой «Вернуть в работу». Аналог Vulnerability Exceptions (Rapid7) и Recast/Accept (Tenable).
- **Проекты**: прогресс устранения по меткам экземпляров (`jira:KEY`, `proj:название`) по факту сканирования: устранено + исключено / всего. Аналог Remediation Projects (Rapid7).
- **Обзор**: соблюдение сроков в трех состояниях «в срок / истекает (80% срока) / просрочено» по каждому уровню опасности, как виджет SLA в Rapid7.
- **Очередь**: фильтры эксплуатируемости (трендовые, эксплойт, critical, есть патч), как фильтры Findings в Tenable.

## Версия 0.4: кликабельные показатели, ОС и контейнеры, риск по методике ФСТЭК, инвентаризация

- **Обзор.** Каждый показатель кликабелен: открывается панель выборки с таблицей (CVE со ссылкой на паспорт, узел со ссылкой на карточку, уровень, статус, дата), текстовым фильтром, CSV, копированием PDQL, переходом в список активов MaxPatrol с этим PDQL и кнопкой «В проект» (метка `proj:название` на все экземпляры выборки). Числа в таблице сроков и возраста тоже ведут к выборке. Трендовые CVE открывают паспорт уязвимости (GUID паспорта берется из третьего сегмента `Host.@Vulners.Id`), бейдж KEV ведет в каталог CISA, узлы в топ-10 открывают карточку актива. Отчет для руководства: открыть, скачать HTML, печать в PDF. Область не грузит систему при открытии: показывается последний снимок, пересчет по кнопке.
- **Очередь.** Третий источник «Операционные системы» (`Host.@NodeVulners` по `OsName` + `OsVersion`): обновления ОС, которых не было в очереди по ПО и пакетам. В деталях группы CVE ведут в паспорт, узлы в карточку, кнопка «В проект».
- **Таблицы как в Excel (0.4.1).** Во всех таблицах: клик по заголовку сортирует (числа и строки), значок в заголовке открывает список уникальных значений колонки с поиском и чекбоксами, правый клик по ячейке оставляет только строки с этим значением, активные фильтры показаны чипами со сбросом, над таблицей общий текстовый поиск. Заголовки с заглавной буквы. Стили таблиц, заголовков секций, бейджей и цветных счетчиков сняты с паспорта уязвимости 28.0 (14px без рамок, заголовки секций TT-Positive 18px, хлебные крошки «Устранение уязвимостей / вкладка» в шапке).
- **Риск активов (0.4.1, гибридная модель).** Четыре компонента с потолками: экспозиция E (объем открытых: critical x40, high x8, medium x1.5, low x0.3, логарифмическая шкала, до 400), опасность V (max и средний CVSS, до 150), угроза T (трендовые, эксплойты, RCE, CISA KEV, до 250), критичность по методике ФСТЭК F (оценка худшей уязвимости, коэффициент kK из значимости актива: высокая 0.4, средняя 0.32, низкая 0.2; периметр не учитывается, до 200). Риск = (E + V + T + F) x контекст (значимость H 1.2 / M 1.0 / L 0.8 / ND 0.9, скан старше 30 дней 1.05), потолок 1000. Потолки и множители настраиваются в «Настройках». Кнопка «Уточнить по KEV» проверяет CVE с эксплойтом по каталогу CISA, «Теги зон риска» ставит `auto:risk-critical/high/medium/low`. На стенде: медиана 693, критических 169 из 341.
- **Инвентаризация (0.4.1).** 22 правила в шести группах: платформа (Windows, Linux, ОС снята с поддержки), роль (сервер, рабочая станция, сетевое, сервер БД и веб по открытым портам, RDP, SSH), расположение (публичный IP вне RFC 1918 через CIDR в PDQL), гигиена (без значимости, аудит старше 30 дней, скан не выполнялся), угроза (трендовые, critical, эксплойт, RCE), сроки (просрочен critical/high по приказу 117, патч есть дольше 90 дней, «Новая» старше 30 дней). По умолчанию отмечены статичные группы; правила угрозы и сроков применяются после сканирования.
- **Риск активов (первая редакция 0.4).** Формула по методике ФСТЭК: оценка уязвимости `CVSS x I x (Ii + Iat)`, где `I = kK + lL + pP` (тип актива Server/Network 0.32, Desktop 0.2, группа критически важных 0.4; периметр 0.4 / 0.2), `Iat` трендовая 0.6 / эксплойт 0.3 / иначе 0.1, `Ii` RCE и LPE 0.5, DoS 0.26, иначе 0.12. Сумма по открытым уязвимостям узла с весом значимости, сжатая в 0-1000 логарифмом. Уровень худшей уязвимости узла по ФСТЭК (critical > 8, high >= 5, medium >= 2). Виджеты: зоны риска, по значимости, по типу актива, по ОС; названия групп периметра и критически важных активов настраиваются. Клик по узлу показывает его уязвимости.
- **Проекты.** Клик по проекту показывает его уязвимости и узлы; кнопка «Закрыть» снимает метку со всех экземпляров.
- **Контейнеры и веб.** Сводка по наборам образов (`ImageSet.Images.Packages.@Vulners`), очередь по пакетам образов с CVE, уязвимости веб-сайтов (`WebSite.@Vulners`).
- **Инвентаризация.** 11 правил авто-тегов (`auto:os-windows`, `auto:os-linux`, `auto:type-server`, `auto:type-workstation`, `auto:type-network`, `auto:no-importance`, `auto:stale-scan`, `auto:has-trending`, `auto:has-critical`, `auto:has-exploit`, `auto:rdp-open`) плюс свое правило (имя тега + PDQL с `select(@Host)`). Тег создается через `POST /api/tags/v1/asset/tags` и назначается каждому активу выборки через `PUT /api/tags/v1/entities/asset/{id}` (8 запросов параллельно; батч `POST /api/tags/v1/entities/asset/tags` с `selectionId` сервер 28.0 принимает, но без выборки грида не применяет). Покрытие тегами, список тегов, удаление всех `auto:*` одной кнопкой.
- **Jira.** В задаче целевая версия: из раздела «Как исправить» паспортов трех самых опасных CVE группы берется максимальная версия той же ветки, что текущая (для `OpenSSL 3.0.2` из «3.0.15, 3.1.7, 3.2.3» будет 3.0.15). Плюс рекомендации из паспорта, ссылки на патчи и бюллетени из NVD, контекст узлов: значимость, ОС, группы.
- **Везде.** Текстовый фильтр над таблицами, заголовки колонок по-русски, ссылки на паспорт уязвимости и карточку актива, переходы в БДУ (`bdu.fstec.ru/search?q="CVE"&yt0=Искать`) и dbugs (`dbu.gs/vulnerability/<CVE>`).

- **Снимки состояния (0.5).** Результат каждой вкладки (обзор, очередь с параметрами, риск активов, исключения, проекты, контейнеры и веб, инвентаризация, CVE-контекст) сохраняется в `chrome.storage.local` и живет сутки: при открытии области показывается последний снимок с подписью «снимок от ..., обновление по кнопке», система не нагружается повторными PDQL.
- **Отчеты по каждой вкладке (0.5).** В шапке области кнопки «Отчет: HTML | PDF | CSV» действуют на открытую вкладку: HTML скачивается файлом, PDF открывает окно печати (сохранить как PDF), CSV выгружает таблицу. Отчет содержит сводку, ключевые показатели и таблицы вкладки (для очереди: группы и выбранная группа с CVE и узлами; для риска: зоны, разрезы и активы; для исключений: причины, сомнительные и по узлам; для CVE: вердикты, CVSS, EPSS, KEV, SSVC, БДУ).

## Доработки штатных экранов (по аудиту `../UI_AUDIT_28.0.md`)

- **Карточка и паспорт уязвимости.** Блок «Внешний контекст»: ссылки NVD, cve.org, dbugs (PT), поиск в БДУ, Vulners, GitHub; по кнопке EPSS, KEV, SSVC, CVSS 4.0, вердикт и прямые ссылки на патчи и бюллетени вендора из NVD (теги Patch, Vendor Advisory, Mitigation).
- **Карточка актива.** Кнопки «Выгрузить уязвимости актива в CSV» и «Задача в Jira по активу» (одна задача на узел, CSV во вложении, метка `jira:KEY` на экземпляры).
- **Дашборд.** Опция «переходы в текущей вкладке» (перехват `window.open` на том же origin через `content/inject.js`; Ctrl/Cmd+клик оставляет новую вкладку).

## Jira

Настройки во вкладке «Настройки» рабочей области: адрес, тип аутентификации (Cloud: email + API token, Basic; Server/DC: персональный токен, Bearer), проект, тип задачи, метки. Кнопки «Проверить подключение» (`/rest/api/2/myself`, `/serverInfo`) и «Список проектов».

Две модели задач:
- из очереди устранения: одна задача на решение (ПО + версия) с таблицей CVE (CVSS, EPSS, KEV, трендовость), списком узлов, приоритетом (P0-P3 → Highest…Low), сроком и CSV-вложением; метка `jira:KEY` ставится на экземпляры уязвимостей через `ChangeTagsCommand`, «Найти существующие» ищет по JQL `labels = mpvm-<по>`;
- из карточки актива: одна задача на узел со сводкой по уровням и топ-40 уязвимостей, полный список в CSV.

Отличие от стороннего скрипта с портала дополнений PT (`OlegKocha/mpvm-jira-integration`, одна задача на актив, XLSX, без поиска дублей и обратной связи): здесь задачи создаются из интерфейса по кнопке, есть группировка по решению, поиск существующих задач по метке и метки на экземплярах в MaxPatrol.

## Архитектура

```
content/api.js    запросы к MaxPatrol со страницы стенда: тот же origin, Bearer-токен (без OAuth и cookie)
content/logic.js  PDQL-запросы очереди и метрик, массовые операции, разбор БДУ
content/app.js    пункт меню (клон .kbq-navbar-item «Активы») и рабочая область в shadow DOM, тема через CSS-переменные Koobiq
content/cards.js  доработки штатных экранов: блок в карточке уязвимости, кнопки в карточке актива, инъекция inject.js
content/inject.js выполняется в контексте страницы: window.open на тот же origin в текущей вкладке
background.js     внешние источники (EPSS, KEV, NVD, GitHub), Jira REST, настройки, кэши в chrome.storage.local
popup.html/js     сервер, порт, токен; проверка через content-скрипт открытой вкладки
```

Внутренние API интерфейса (не из публичного devguide), на которых держится модуль:

| Назначение | Запрос |
|---|---|
| PDQL | `POST /api/assets_temporal_readmodel/v1/assets_grid` → `GET .../assets_grid/data?pdqlToken=` (404 пока не готово) |
| Массовые операции | `POST /api/vulnerabilities_processing/v1/assets_vulnerabilities/operations` `{type, vulnerabilitiesInstancesIds, tillDate?, statusReason?, statusNote?}`; состояние `GET .../operations/{id}` → `{totalCount, succeedCount}` |
| Доступные команды | `GET .../operations/commands?statuses=new` |
| Версия | `GET /api/deployment_configuration/v1/system_info` |

| Список активов с запросом | `/mpx/common/am/assets?groupId=<группа>&pdqlQuery=<PDQL>` (так переходят виджеты дашборда; параметр `pdql` страница игнорирует; `queryId` необязателен). Карточка актива: `...&viewMode=list&assetId=<id>&tabName=summary`. Паспорт уязвимости: `/mpx/vm/vulnerability-passport-card?vulnerabilityId=<guid>` |
| Паспорт уязвимости | `GET /api/assets_temporal_readmodel/v1/vulnerabilities/{guid}` (title, description, howToFix, links, cvss3Metrics, isTrend, hasExploit) |
| Теги активов | `GET/POST /api/tags/v1/asset/tags`, `DELETE .../tags/{id}`, `PUT /api/tags/v1/entities/asset/{assetId}` `{tagIdsToAdd, tagIdsToRemove}` |

Идентификатор экземпляра уязвимости для операций: `Host.Softs.@NodeVulners.Id` / `UnixHost.Packages.@Vulners.Id` / `Host.@NodeVulners.Id` (ОС). Третий сегмент составного Id (32 hex) - GUID паспорта: `/mpx/vm/vulnerability-passport-card?vulnerabilityId=<guid>`.

Особенности PDQL 28.0, найденные при разработке: в `then`/`else` только литералы (`then Score` дает 400), арифметика в `calc` работает без скобок (`calc(Score * fT as vT)`), имена полей уникальны без учета регистра (`sT` и `ST` конфликтуют), `Host.@Tags.Item` возвращает объект `{displayName, color}`, но сравнение `Host.@Tags.Item = "имя"` работает.

## Ограничения

- Внутренние API меняются между версиями продукта (на 28.0 путь чтения PDQL отличается от 2.10). Проверено только на 28.0.
- Права определяет владелец токена: список доступных команд смены статуса запрашивается у сервера.
- `timepoint` на 1,5 млн уязвимостей выполняется 3-4 минуты, поэтому история выключена по умолчанию.
- bdu.fstec.ru не отдает данные скриптам: только ручной импорт выгрузки.
